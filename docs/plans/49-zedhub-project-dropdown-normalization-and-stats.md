# 实施计划 - zedhub 项目下拉框路径规范化、去重与数量统计增强

**问题陈述**：
当前 Web UI 的【项目】下拉筛选框存在严重的数据与视觉缺陷（参见用户截屏反馈）：
1. **数据断层与缺失**：上半部分项目来自 `/api/v1/projects`（Zed 索引），带有详细的 `X 活跃 / Y 总计` 格式；下半部分项目是后续从 `/api/v1/search` 的 `hit.projects` 中追加的，追加代码仅简单赋予 `opt.textContent = basename(project)`，完全没有统计数量，导致下半段项目没有任何数字数据；
2. **正反斜杠与大小写导致重复项**：Zed 项目路径与外部发现项目路径格式不一致（例如 `D:\Users\language_projects` vs `D:/Users/language_projects`），原去重逻辑使用原生字符串 `Set.has(project)` 进行全等匹配，导致同一项目（如 `pnpm_ts`、`study-cn-by-ai`）在上下两段均出现；
3. **缺乏层级结构与数量排序**：项目下拉框没有像 Agent 下拉框那样使用 `<optgroup>`（`Zed 管理项目` vs `外部发现项目`）进行层级组织；且列表未按项目下关联的会话数量降序排序（用户期望“多的排在前面”）。

**需求**：
1. **回答用户根因**：清晰剖析为什么当前下拉框下半部分完全没有数据，以及为什么会出现重复；
2. **路径规范化去重**：前端定义标准路径归一化函数（统一正斜杠、统一大小写规范），确保同一个物理项目在 Zed 索引与外部发现中精确识别合并，彻底杜绝重复；
3. **全量项目统计与数据呈现**：
   - 对外部发现的项目，通过统计 search hits 中的实际频次，统一展示数量（例如 `(N 会话)` 或全量 `活跃 / 总计`）；
   - 每个项目都有明确的数量标识，杜绝无数据的“裸项目名”；
4. **层级结构与排序优化（多的在前面）**：
   - 采用与 Agent 下拉框一致的体验：可选用 `<optgroup>` 分组（`Zed 管理项目` / `外部发现项目`）或统一智能合并；
   - 每个分组内部均按**会话数量降序排序**（数量多的排在前面，相同数量按名称字母升序）；
5. **回归测试保障**：补充前端或后端相关测试，确保筛选和数据加载稳定。

**任务分解**：
- [x] Task 1: 编写项目下拉框路径归一化函数与外部项目频次统计逻辑（app.js）
- [x] Task 2: 项目下拉框支持层级分组（optgroup）与会话数量降序排序（app.js）
- [x] Task 3: 优化项目展示文案与路径匹配（value 统一，避免路径斜杠差异导致筛选失效）
- [x] Task 4: 自动化测试与全量回归验证

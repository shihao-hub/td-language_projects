# 计划：强制 plans/specs 变更独立提交

**问题陈述**：当前根目录 `AGENTS.md` 尚未明确要求 `**/plans/**` 与 `**/specs/**` 下的文件独立提交，后续计划或规格文档可能与代码及其他文件混合提交，难以通过 Git 历史单独查看每次计划的变更。需要补充一条仓库级强约束，确保这两类目录中的任何新增、修改、删除或重命名都进入独立 commit，并允许 Agent 在无需再次征得用户同意的情况下完成对应提交。

**需求**：

1. 修改根目录 `AGENTS.md`，新增 `**/plans/**`、`**/specs/**` 变更的独立提交规则。
2. 规则覆盖新增、修改、删除、重命名等文件变更。
3. 相关 commit 不得混入代码、配置或其他无关文件，也不得与其他计划/规格文件变更混合，以便按单个 plan/spec 追踪历史。
4. Agent 对这类独立 commit 不需要再次征得用户允许；只有提交因 Git 身份、权限、钩子、冲突或其他安全边界无法完成时才询问用户。
5. 不把当前工作区中已有的其他未提交变更纳入本次修改或提交。

**背景**：

- 当前仓库根目录是 `D:/Users/language_projects`，父仓库使用中文 commit message 约定。
- 文档计划统一位于父仓库的 `docs/plans/`；项目计划和规格文档还可能位于 `**/plans/**`、`**/specs/**` 的其他路径。
- 当前工作区已有与本任务无关的修改和未跟踪文件，包括已有的 plan/spec 文件；本次必须保持范围隔离。
- `AGENTS.md` 顶部已有 Git commit message 与提交范围隔离规则，适合在该区域补充本规则。

**方案**：

1. 在 `AGENTS.md` 的 Git 提交约定附近增加独立提交规则，明确匹配范围、变更类型、提交隔离、自动提交授权和失败询问条件。
2. 仅修改新增规则所需的文本，保留工作区中已有的 `AGENTS.md` 其他改动。
3. 用 `git diff --check` 和定向 diff 检查格式、语义与范围；不运行项目构建或测试，因为本次只涉及仓库约定文档。
4. 计划文件本身按该目标流程独立提交；该提交只包含本计划文件，不包含工作区其他既有变更。

  - 验证：执行 `git diff -- AGENTS.md` 与 `git diff --check`；预期仅出现本规则及当前既有改动，且无空白错误。

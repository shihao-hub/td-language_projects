# taskmon 进程树用途标签与单链压缩

> 状态：已完成（2026-11-19）
> 范围：仅 TUI 进程树视图；不改 WebUI、不改 `--once` 输出布局。

## 背景

截图中的 TUI 进程树只显示 `进程名 + (子节点数)`，看不到命令行；而一台开发机上
`powershell.exe → node.exe → node.exe → codex.exe → conhost.exe` 这类深度 4~5 的单孩子链
非常常见。要看清「这堆 powershell 到底在跑什么」，必须逐层按 Enter 展开多次。

实机采样确认命令行的信息量足够提炼用途：

- `powershell.exe -C "...\Zed\external_agents\registry\claude-acp\..."` → `claude-acp`
- `powershell.exe -C "node ...codex-acp\node_modules..."` → `codex-acp`
- `node.exe ...pi-coding-agent\dist\bundle\cli.js --mode rpc` → `pi-coding-agent`
- `node.exe ...agy-bridge\bin\launch.mjs` → `agy-bridge`
- `node.exe ...dsh\lib\bin.js web --port 11111` → `dsh`
- `node.exe ...chrome-devtools-mcp\...` → `chrome-devtools-mcp`

`ProcessInfo.commandLine` 已由 CIM 拓扑采集补齐（`mergeTopology`），无需改采集层；
WebUI 树视图早已有命令行列，本次把同等能力以「用途标签 + 链压缩」的形式补进 TUI。

## 目标与验收标准

1. 启动 `pnpm dev --tree`，CIM 就绪后每个 powershell/node 行直接显示用途标签。
2. 单孩子壳链压成一行：`powershell.exe › node.exe › codex.exe +2`；`›` 表示压缩，
   `+N` 为被合并的中间进程数，PID 列显示链尾 PID。
3. 压缩行一次 `Enter` 展开整条链并展开链尾子节点；`←` / `-` 收起。
4. 多孩子节点（`chrome.exe (41)`、`node.exe (4)`）不压缩，原展开语义不变。
5. 搜索、`k` 结束子树、`a` 全展开/收起、`--top`、视口滚动均不回归；
   `--once --tree` 输出与改造前一致（时间戳除外）。
6. 80 列窄终端不换行、不破版（用途列自动隐藏）。
7. `pnpm test`、`pnpm typecheck`、`pnpm build` 全绿。

## 布局

```
 #  进程树                                        用途              PID    自身    子树   占比  分布
 1  wininit.exe (4)                               system           1660  8.72MB  6.35GB 27.4% ███████░
 2  chrome.exe (41)                               editor           10852 369MB   5.84GB 25.2% ██████░░
 3  └─ powershell.exe › node.exe › codex.exe +2   codex-acp        7252  144MB   624MB  2.6%  ████░░░░
 4     └─ conhost.exe                             终端宿主          38364 7.97MB  7.97MB 0.2%  ░░░░░░░░
```

- 列序：`#` | 进程树 | **用途（新）** | PID | [CPU] | [子树CPU] | 自身 | 子树 | 占比 | 分布。
- 压缩行：`自身` = 链内各节点自身内存之和；`子树`/`占比`/`分布` 用链首 subtree（整链）。
- 用途取链内从尾向前第一个非空标签；纯交互 shell 无参数时留空，不伪造信息。
- 用途着色：shell=cyan、runtime=green、agent=magenta、editor=blue、terminal/system=dim；
  内存列红黄绿阈值不变。
- 列宽：`treeW` 上限 40 → 46；用途列宽 12~28，低于 12 视为关闭（窄屏自动隐藏）；
  分布条上限 40 → 32，为用途列让位。

## 实现要点

### 1. 新增 `src/core/purpose.ts`（纯函数）

- `tokenizeCommandLine(cmd)`：处理双引号/单引号、`\"`、未闭合引号，空 token 丢弃。
- `PurposeKind = shell | runtime | agent | editor | terminal | system | other`；
  `purposeOf(p: ProcessInfo): { kind, label }`。
- 壳包装递归：`powershell/pwsh/cmd/bash/wsl` 解析 `-Command/-C/-File/-f/c /c` 后续内容，
  首 token 是 exe 则继续递归，最多 3 层并用 seen 集合防环。
- `node/bun/deno`：`-e/--eval` → `eval`；脚本路径 → 模块标签：
  路径含 `node_modules` 取最后一段之后的首个包名（跳过 `.pnpm`、支持 `@scope/name`）；
  否则取脚本 basename，父目录为 `dist/bin/lib/build/src/bundle/releases` 或版本号目录时上提一层。
- `.ps1/.cmd/.bat/.py` → 文件名；其他 exe 取首个非 flag 参数的 basename。
- 无命令行/解析失败 → label 为空，仅按进程名给 kind。

### 2. `src/core/proctree.ts`：新增 `flattenTreeCollapsed`

- `interface TreeChainRow extends TreeRow { head: ProcessTreeNode; chain: ProcessTreeNode[] }`。
- 仅当节点未展开且恰有 1 个孩子时沿链下探；链内至少一个节点属壳族
  （`powershell.exe/pwsh.exe/cmd.exe/node.exe`）才压缩，系统单链不压。
- 链延伸不吸收 `conhost.exe`（链尾停在 conhost 之前，conhost 仍可展开）。
- `node` = 链尾，`hasChildren/expanded` 按链尾算，`isLast` 沿用链首位置。
- 保留旧 `flattenTree` 与其余导出不变。

### 3. `src/cli/render.ts`

- `TreeRenderOptions` 增 `collapseChains?: boolean`（默认 true）、`showPurpose?: boolean`（默认 true）。
- `renderTreeFrame` 改用 `flattenTreeCollapsed`，新增链标签生成与用途列。
- 列宽统一按 gap 数推导（有/无 CPU、有/无用途列分别计数），避免魔法数漂移。
- 用途文本先 `truncate` 再着色；反色只覆盖主文本，颜色不参与反色范围。

### 4. `src/cli/main.ts`

- `shownTreeRows()` 改用 `flattenTreeCollapsed`，保证渲染与光标同源。
- 新增 `showPurpose = true`，`d` 键切换；状态栏提示追加 `d 用途(开/关)`。
- 压缩行 `Enter`：链内全部 PID 加 `expandedNodes`（含链尾）；
  `←`/`-`/再次 `Enter`：删除整条链 PID。
- `startKillConfirmTree` 以 `row.head` 构造伪分组（等价改造前选中链首的子树 kill）。
- 搜索：按 `chain.some(pid)` 定位压缩行，命中中间节点时展开祖先链。
- `--once` 显式传 `collapseChains: false, showPurpose: false`。

### 5. 文档

- 更新 `README.md`：树视图说明、`d` 键、压缩语义、用途来源与「无法获知工作目录」的限制。

## 边界与失败模式

- CIM 未就绪/失败：用途列留空，树照常（沿用现有拓扑降级）。
- 受保护进程（cmd=null）、空命令行、未闭合引号：tokenizer 不抛异常。
- 链压缩 + `--top`：top 只裁剪根，不影响链。
- 链压缩 + `a`：全展开不压缩；全收起恢复压缩（沿用 toggleAll 语义）。
- 链压缩 + kill：选中压缩行 = 结束链首子树，护栏按链首名 + 全子树判断。
- 终端 resize：每帧重算列宽；窄屏自动隐藏用途列。

## 实施记录（与原计划的差异）

- **conhost 不计入单孩子判定**：实机发现 powershell 通常同时挂着 node 与 conhost 两个孩子，
  按原规则 `children.length === 1` 永不压缩；改为按"实质孩子"（排除 conhost）判定，
  conhost 仍可作为链尾子节点展开。
- **链名压缩显示**：只显示链首与链尾（`>2` 段用 `…` 省略中间），并去掉 `.exe` 后缀，
  显示形如 `powershell › … › codex +3 (3)`；`+N` 为链内被合并的中间进程数，
  括号为链尾子节点数（含 conhost）。
- **treeW 取最长可见行**：原实现 `Math.min` 取最短行导致长链必然截断，改为取最长并
  cap 48；分布条上限相应降到 32 给用途列让位。
- **用途噪音过滤**：非 flag 首参排除 `key=value`、GUID、纯数字串；与进程名重复的标签
  （如 `adb.exe` → `adb`）置空。
- 实机验证：Zed 下 5 条 powershell 链均压缩为一行并显示
  `@openai/codex`、`claude-agent-acp`、`opencode`、`agy_acp_server`、`@moonshot-ai/kimi-code`；
  `--once --tree` 输出与改造前一致（无用途列、无压缩）。
- **AOCI**：收尾调用 `aoci_maintain` 返回 blocked——整仓索引存在与本次改动无关的既有漂移
  （`docs/plans/` 旧路径缺失、大量 orphan/unbaselined 条目），本次未产生元数据变更；
  该债务需单独开仓库级维护任务，不在本计划范围内强行修复。

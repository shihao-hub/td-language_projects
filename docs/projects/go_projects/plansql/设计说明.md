# plansql 设计说明

## 1. 产生背景

在大型项目管理中，Markdown 格式的 `plans` 和 `specs` 随版本迭代迅速增多。传统方案中：
- 直接使用 SQLite 二进制数据库会导致 Git 出现二进制冲突且无法合并；
- 让大语言模型直接维护手写 SQL 则极易出现字符串转义失误、语法错误或路径不规范；
- 状态缺乏机器可读和直观监控手段。

## 2. 架构设计

本项目遵循仓库规范《CLI 工具开发标准 v2》的 daemon 架构：

- **真理层 (Source of Truth)**：`plans_status.sql` 纯文本，只追加不覆盖（Append-Only）。
- **投影层 (Materialized View)**：纯内存 SQLite 数据库（由 `modernc.org/sqlite` 驱动提供，零 CGO 编译依赖）。
- **Daemon 层 (`plansql serve`)**：提供 HTTP+JSON API，挂载内嵌的纯 HTML5/CSS/JS 看板页面，支持闲置超时优雅关停。
- **薄客户端 (Shells)**：
  - `CLI`（`list` / `set` / `check` / `scan` / `ui` / `where`）
  - `MCP Server`（stdio 协议供 AI 自动化调用）
  - `Web UI`（浏览器可视化仪表盘）
  - `GUI`（Wails v3 桌面工作台，托盘常驻）

## 3. 双通道产物与桌面壳

按《sh-go-wails-desktop》标准拆成两条通道，每条通道各出两个二进制：

| 通道 | dev | release | 职责 |
|---|---|---|---|
| GUI | `plansql-gui-dev.exe` | `plansql-gui.exe` | 只显示桌面壳，不解析任何子命令 |
| Console | `plansql-cli-dev.exe` | `plansql-cli.exe` | 终端 / 脚本 / Agent / MCP |

- GUI 内嵌独立 HTTP 服务（动态端口），与 CLI `serve` 共用 `daemon.Server.Handler()`；它不写 `plansql.addr`，不会冒充可被 CLI 发现的共享 daemon。
- GUI 记忆上次项目根（`project.json`），首次启动弹出目录选择；托盘与 WebUI 顶栏均支持切换项目，切换时重建投影并重放 SQL，失败保留旧状态。
- 窗口尺寸、位置、最大化状态落在 `window.json`，几何事件 700ms 防抖保存，关窗前同步补存。
- dev / release 在产物名、版本号、数据目录、单实例 ID、图标五个维度完全隔离；数据目录为 `%APPDATA%\language_projects\plansql\{dev,prod}`。

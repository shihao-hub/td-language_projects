# agyquota 设计说明

> 记录 Antigravity 配额查询的接口调研结论、429 封锁的完整调查过程与复活路径。工具代码见 `go_projects/agyquota`。

## 1. 目标与现状

目标：不打开 Antigravity IDE 查询模型配额（Gemini / Claude and GPT 两桶，Weekly + Five Hour 窗口剩余百分比与重置时间）。

现状：工具全链路代码就绪（凭据 → OAuth 刷新 → 接口调用 → 解析归一化 → CLI/MCP/契约），唯一卡点是 Google 对配额接口做**客户端身份校验**，非 IDE 请求一律 429。

## 2. 接口地图（逆向自 language_server.exe 2.15.1）

### 2.1 端点

| 通道 | 主机 | 形态 |
|---|---|---|
| REST JSON | `https://daily-cloudcode-pa.googleapis.com/v1internal:<Method>` | POST，proto3 JSON |
| gRPC | 同域，路径 `/google.internal.cloud.code.v1internal.<Service>/<Method>` | HTTP/2 + protobuf |
| JetskiService | `https://aicode.googleapis.com`（gRPC-only） | agent 会话类服务 |

另有 `cloudcode-pa.googleapis.com`（无前缀生产域）与 sandbox/autopush 变体，行为一致。

### 2.2 关键方法（gRPC 服务/方法）

| Service | Method | 说明 |
|---|---|---|
| `PredictionService` | `FetchAvailableModels` | 模型列表 + `quotaInfo{remainingFraction, resetTime, window_size}`（设置面板数据源，REST 路由 `:fetchAvailableModels`） |
| `PredictionService` | `RetrieveUserQuota` / `RetrieveUserQuotaSummary` | 聚合配额桶（响应含 `buckets` / `groups` 字段） |
| `CloudCode` | `LoadCodeAssist` | 套餐信息（不封锁，可完整调通） |
| `JetskiService` | `FetchUserInfo` 等 | 需 IDE 会话权限 |

### 2.3 鉴权

凭据落盘于 `~\.gemini\antigravity-acp\acp_token.json`（Zed ACP antigravity agent 写入）：

```json
{
  "client_id": "1071006060591-....apps.googleusercontent.com",
  "client_secret": "GOCSPX-...",
  "refresh_token": "1//...",
  "token_uri": "https://oauth2.googleapis.com/token",
  "scopes": ["cloud-platform", "userinfo.email", "aicode"],
  "project_id": "aicode-consumers"
}
```

注意：`scopes` 可能是字符串或数组（两种形态都出现过），解析须宽松。刷新 access token（`grant_type=refresh_token`）离线可用、长期有效，与 IDE 共享同一 OAuth client（client_id/secret 已在 LS 二进制中验证一致；二进制内共嵌两套 client，另一套 `884354919052-...` 为受限 client，浏览器授权流被 Google 以 `restricted_client + Unregistered scope: aicode` 拒绝）。

### 2.4 请求结构（Proto 还原）

- `FetchAvailableModelsRequest{project, requestId, entitlement{userTier}, location}`——`Entitlement` 消息仅含 `userTier` 字段；`userTier` 的合法值不在二进制常量中（应来自服务端下发）。
- `RetrieveUserQuotaSummaryRequest{project, forceRefresh, request?}`。

## 3. 429 封锁调查记录（2026-09-22）

### 3.1 实验矩阵与结论

| 变量 | 结果 |
|---|---|
| 默认请求（REST/gRPC、daily-/生产域、IDE 开/关） | 一律 429 RESOURCE_EXHAUSTED |
| 伪 jetski 身份头（UA + x-goog-api-client） | 429 → NOT_FOUND（"Requested entity was not found"，说明已路由到配额注册表，缺 entitlement 等字段） |
| `x-goog-user-project` | → PERMISSION_DENIED（serviceusage 权限） |
| `LoadCodeAssist` | 始终 200（不封锁），且返回 "This client is no longer supported... migrate to Antigravity" |
| scope 扩展 | refresh 拒绝追加 scope（400） |
| client #2 浏览器授权 | `restricted_client`（aicode scope 未注册公开授权） |

### 3.2 结论

Google 按**客户端身份头**分类：无身份头软封锁（429）；伪 jetski 身份可到达配额注册表但缺 entitlement/完整请求形状（NOT_FOUND）。已排除：凭据差异（与 IDE 同 client）、并发抢占（IDE 关闭后仍 429）、协议差异（JSON 与 gRPC 同样 429）、域名差异（daily-/生产一致）。

### 3.3 MITM 抓包尝试（死因）

本机代理（自签 CA 动态伪造叶子证书 + HTTPS_PROXY 劫持 LS）验证结论：

1. LS 的 **gRPC 通道证书锁定**（内置 Google 根证书池，拒收用户安装的 CA：`tls: bad certificate`）；
2. LS 的 REST 客户端（h2c prior knowledge，无 ALPN）**同样使用自定义证书池**（`x509: certificate signed by unknown authority`）；
3. 仅无关组件（系统证书库信任的 h1 客户端）接受自签 CA，但无业务请求。

即 IDE 的全部关键通道都无法在本机透明抓包。

### 3.4 复活路径

- 若 Google 放开非 IDE 客户端 → 现有代码直接可用（可能只需调 UA）；
- 若拿到 IDE 真实请求形状（UA / x-goog-api-client / entitlement 值）→ 仅需修改 `internal/agapi/client.go` 的请求构造；响应解析已按 `quotaInfo{remainingFraction, resetTime}` 防御式实现；
- IDE 运行期间也可从其本地 LS 端口取数（`%APPDATA%\Antigravity\logs\language_server.log` 记录随机端口），可作为未来 "via-ide" 模式。

## 4. 工程结构

```
cmd/agyquota/          组装入口 + 图标资源
internal/agapi/        基础设施：凭据读取、OAuth 刷新、配额接口调用（429 退避 15s/45s/90s）
internal/service/      公共核心：错误契约、响应解析归一化（模型桶 × 窗口）
internal/cli/          CLI 适配器：人读表格 / --json 信封 / 退出码映射
internal/mcp/          MCP stdio server（agyquota.quota.get）+ schema 导出
```

遵循《CLI 工具开发标准》：双入口同源契约、JSON 信封 `{"ok",...}`、退出码 0/1/2、`--help/--version/schema` 不触发业务调用。

## 5. 已验证客户端

- opencode（本工具开发环境）下 CLI 人读/JSON、schema 导出冒烟通过；
- MCP stdio 未做第三方客户端实连（SDK in-memory 发现与注册同源校验通过）。

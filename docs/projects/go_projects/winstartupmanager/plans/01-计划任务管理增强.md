# winstartupmanager 增强计划：计划任务从只读看板升级为可管理

> 2026-11-08 · 触发背景：rebootremind（HOURLY 定时巡检计划任务）在现有看板不可见、不可管。

## 1. 目标

把「计划任务」板块从**只读 Boot/Logon 看板**升级为**自启与定时周期任务的可管理面板**；能看到并启停/删除 rebootremind_check 这类自装巡检任务。项目名不改。

## 2. 已确认决策

- **管理动作集**：启停 + 删除（删除前备份任务 XML）+ 定位 exe；不加「立刻运行」。
- **采集范围**：Boot / Logon / 定时周期触发（每小时、每天、每周、每月、间隔重复）；仍跳过 `\Microsoft\` 系统维护子树。**不收** Event / Idle / SessionStateChange 触发器。

## 3. 方案设计

### 3.1 扫描扩展（internal/engine/tasks.go）
- 触发器类型白名单（TASK_TRIGGER_TYPE2）：`BOOT(8) / LOGON(9) / TIME(1) / DAILY(2) / WEEKLY(3) / MONTHLY(4) / MONTHLYDOW(5)`，任一命中即采集；
- 采集时记录**完整任务路径**（`\rebootremind_check` 或 `\dir\name`）：遍历子文件夹时下传 folder 前缀；
- `StartupItem.ID` 改用 `GenerateID(SourceTaskScheduler, taskPath)`（名可重，路径唯一）。

### 3.2 模型扩展（internal/model/model.go）
`StartupItem` 新增（snake_case 对齐现有 json 契约，任务外来源为空值）：

| 字段 | 含义 |
| :--- | :--- |
| `trigger_desc` | 触发描述（如「开机时」「登录时」「每小时」「每天」） |
| `task_path`    | 集成任务完整路径（`\folder\name`） |
| `next_run`     | 下次运行时间（COM `RegisteredTask.NextRunTime`，取不到为空） |
| `last_run`     | 上次运行时间 |
| `last_result`  | 上次退出码（`LastTaskResult`，0 为正常） |

### 3.3 管理动作（新增 internal/engine/task_actions.go）
- **启停**：读取 `RegisteredTask.Definition`，翻转 `Definition.Enabled`，经 `RegisterTaskDefinition(path, def, TASK_UPDATE=6, ...)` 回写（COM 与项目注册表链路同源，不外弹 schtasks 子进程）；
- **删除**：`Definition.XmlText` 先落 `backups/<task_path>.xml`（路径分隔符转 `_`，防非法文件名字符），再 `ITaskFolder.DeleteTask(path, 0)`；备份失败则中止删除；
- **定位**：复用现有 `LocateInExplorer(exePath)`，前端放开按钮。

### 3.4 service 与前端
- `StartupAppService` 新增 `ToggleTask(taskPath, enable)`、`DeleteTask(taskPath)`，不与注册表 `ToggleItem/DeleteItem` 混签；
- 前端 `types.ts` 增字段；`TaskTable.vue` 增：开关（启停）、删除按钮（复用 DeleteModal 确认）、定位按钮、「触发」「下次/上次运行」列；
- `App.vue` 计划任务计数徽标与刷新逻辑同步适配。

### 3.5 边界纪律
- 删除/停用对**用户区任务**（`\` 与非 Microsoft 子树）无需提权；非管理员进程遇到系统区任务失败时按既有错误提示链路报告；
- dev 通道**允许**管理任务动作（本工具的有效载荷就是管理本身；「dev 拒写注册表」红线仅约束自身开机自启注册，与本功能无关）；
- 删除含确认模态 + XML 备份双保险，对齐注册表项的删除哲学。

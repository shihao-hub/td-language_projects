# 02 数据工厂

对应实验：`apps/data_factory`。「模型上限由数据决定」——微调八成的功夫在数据。

制度文档（Word）放到 `%APPDATA%\language_projects\llm-finetune-lab\corpus\`，全程本地处理。

```powershell
uv run python -m apps.data_factory --scenario all      # extract + chunk + stats
uv run python -m apps.data_factory --scenario generate --limit 20   # 试点
uv run python -m apps.data_factory --scenario generate              # 全量（可 Ctrl+C 随时中断续跑）
uv run python -m apps.data_factory --scenario assemble
uv run python -m apps.data_factory --scenario split
uv run python -m apps.data_factory --scenario qc       # 人工抽检表 qc_samples.md
```

## 一、为什么「直接把文档喂给模型」不行

SFT 的训练目标是「看到这个问题，产出那个回答」。直接拿原文当训练文本，模型学的是「背诵全文」，学不会「员工怎么问 + 助手怎么答」。所以数据工厂要做的三件事：

1. **QA 对**（模型学会「按条文回答」的行为）；
2. **条文背诵样本**（强化关键条款的逐字记忆）；
3. **拒答样本**（文档没有的就答「未找到相关规定」，这是「强约束」的灵魂）。

## 二、流水线五级

```
Word(.docx) → 01_extracted.jsonl → 02_chunks.jsonl → 03_qa_raw.jsonl → 04_sft_all.jsonl → train/val/test.jsonl
              段落/标题/表格交错     结构感知分块       Ollama 合成 QA      组装三类样本       按块分组切分
```

### extract：表格也要、顺序别乱

`python-docx` 的 `doc.paragraphs` 会**丢掉表格与相对顺序**。正确做法是遍历 body 的 XML 子元素，段落与表格按原始顺序交错输出（`docx_extract.py`）。表格转成「表头：值」文本行，报销标准表这类信息才能进入 QA 上下文。

标题识别：样式名 `Heading N / 标题 N` 优先，正文里「第X章」「一、」开头做启发式兜底。**没有标题的分块质量会明显下降**——如果 doctor 阶段发现零标题，先回 Word 把章节套上「标题」样式。

### chunk：按章节边界切，每块语义自洽

目标 400 字（±200）。块太大：QA 合成时上下文稀释、答案开始编造；块太小：条文被拦腰截断、背诵样本残缺。`chunk_id` 用内容哈希，保证重跑稳定——这是断点续跑的基础。

### generate：本地 Ollama 合成（实测 13.8s/块）

每块两次调用 `qwen2.5:7b`（`format=json` 强制结构化输出）：

- QA 合成：问题要口语化多样（是什么/怎么办/多少/多久），答案必须出自片段并带条款号；
- 边界问题（uncovered）：生成「主题相关但片段没答案」的问题——它们在 assemble 时变成拒答样本，教模型**不要脑补**。

工程要点：逐行追加写文件 + 启动时读已完成 chunk_id 跳过 → **Ctrl+C 随时中断，重跑即续**。单块失败重试 2 次后记录 error 行，最后统一重试。

1000 页文档 ≈ 50-80 万字 ≈ 1300-2000 块 ≈ 数小时到一天，挂机跑。

### assemble：三类样本 + 去重

| 类型 | 来源 | 作用 |
|---|---|---|
| qa | 03 文件的合成问答 | 学「怎么答」 |
| quote | 正则抽「第X条…。」原文，零成本零幻觉 | 学「逐字背」 |
| refusal | 静态池（20 条常识/闲聊）+ uncovered 边界问题 | 学「没有就拒答」 |

去重按「去标点归一化问题」精确匹配——「迟到多久算旷工？」和「迟到多久算旷工?」只留一条。

### split：按 chunk 分组，防评测泄漏

同一块生成的 QA 如果一半在 train、一半在 test，评测就是在考「背题」。切分以 chunk 为最小单位（8:1:1），refusal 这类无 chunk 归属的样本独立混洗。`split` 场景末尾有泄漏自检。

## 三、质检怎么看（qc_samples.md）

抽样每类 15 条，重点看：

1. QA 答案是否**忠于片段**（合成模型最常见的失败是引入片外信息）；
2. 条款号引用是否正确（表格数据常被安到错误条款上）；
3. 边界问题是否真的「无答案」（生成模型有时会出「片段其实写了」的假边界）。

不合格率高 → 调 `apps/common/prompts.py` 里的 QA_GEN_TEMPLATE 重跑 generate（旧结果删掉 03 文件即可）。

## 四、数据配比建议

合成数据跑完后看 assemble 的统计：qa : quote : refusal ≈ **10 : 4 : 1** 是安全区。refusal 占比过高（冒烟测试就踩过：20/32）会把模型训成「一律拒答」；过低则幻觉率抬头。调比例的方法：改 `--qa-per-chunk` 或增删 REFUSAL_POOL。

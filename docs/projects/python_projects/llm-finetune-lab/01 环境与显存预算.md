# 01 环境与显存预算

对应实验：`apps/env_baseline`。运行：

```powershell
uv run python main.py run env_baseline --scenario all          # info + budget + bench
uv run python main.py run env_baseline --scenario measure --model qwen3-0.6b --mode both
uv run python main.py run env_baseline --scenario measure --model qwen3-4b --mode 4bit
```

## 一、为什么装环境第一步就可能踩坑：sm_120

RTX 50 系（5050/5060/…）是 Blackwell 架构，算力等级 **sm_120**（compute capability 12.0）。PyTorch 只有 **cu128 及以上**的构建才带 sm_120 的核函数；网上老教程普遍让你装 cu121/cu124——装完一跑就是 `no kernel image is available for execution on the device`。

本项目 `pyproject.toml` 已固化正确来源：

```toml
[[tool.uv.index]]
name = "pytorch-cu128"
url = "https://download.pytorch.org/whl/cu128"
explicit = true

[tool.uv.sources]
torch = { index = "pytorch-cu128" }
```

验证：`doctor` 输出 `PyTorch 2.11.0+cu128 + CUDA 12.8 | RTX 5050 Laptop 8.0GB（Blackwell sm_120）`。

bitsandbytes 0.50.2 提供 Windows wheel 且支持 sm_120（实验 04 的 QLoRA 实测通过）。

## 二、显存预算公式（本篇核心）

训练时显存由四块组成：

```
总占用 = 权重 + 梯度/优化器状态 + 激活值 + 框架开销(0.5~1GB)
```

| 组件 | 全参微调 | LoRA | QLoRA |
|---|---|---|---|
| 权重 | P×2 (bf16) | P×2（冻结） | P×0.55（nf4+量化常数） |
| 梯度 | P×2 | 只有适配器（约 0.5~2%×P×2） | 同 LoRA |
| 优化器 | AdamW 约 P×8（fp32 动量/方差） | 适配器×8（很小） | 适配器×8（paged 8bit 更省） |
| 激活 | 巨大 | 梯度检查点后每层只存 1 份输入 | 同 LoRA，另有反量化临时缓冲 |

其中 P 是参数量。对 8GB 显存，代入三个 Qwen3 模型得到决策表（`--scenario budget` 输出）：

| 模型 | bf16 权重 | 4bit 权重 | LoRA-bf16 峰值 | QLoRA 峰值 | 8GB 结论 |
|---|---|---|---|---|---|
| qwen3-0.6b | 1.12 GB | 0.31 GB | ~4 GB | ~2.5 GB | LoRA 宽裕 |
| qwen3-1.7b | 3.17 GB | 0.89 GB | ~7 GB | ~4 GB | LoRA 可行（紧） |
| qwen3-4b | 7.45 GB | 2.05 GB | 不可行（权重就超了） | ~6 GB | 仅 QLoRA |

**结论：0.6B 学流程、1.7B 练手、4B QLoRA 出成品。**

## 三、实测对照（measure 场景的真实输出）

| 模型/模式 | 加载后 allocated | 生成峰值 | 速度 |
|---|---|---|---|
| 0.6B bf16 | 1.11 GB | 1.13 GB | 15.2 tok/s |
| 0.6B 4bit | 0.52 GB | 0.53 GB | 19.2 tok/s |
| 4B 4bit | 2.49 GB | 2.51 GB | 8.2 tok/s |

两个理论 vs 实测的差异值得理解：

1. **4bit 实测（523MB）高于理论（312MB）**：bnb 默认不量化 embedding/lm_head 等层，且每块存量化常数；
2. **4bit 推理反而更快**：带宽瓶颈下，读 4bit 权重的显存流量只有 bf16 的 1/4——显存带宽往往是消费卡推理的第一瓶颈。

## 四、算力基准：先测地板再谈训练时间

`--scenario bench` 实测（4096×4096 矩阵乘）：

- bf16 / fp16：约 **19 TFLOPS**
- fp32（tf32 关闭）：6.7 TFLOPS

训练时间粗估公式：`FLOPs ≈ 6 × P × tokens`，除以有效算力（实测值 × 30%~50% 的利用率）。例：4B QLoRA、5000 样本 × 平均 512 token、3 epoch：

```
6 × 4e9 × 5000 × 512 × 3 ≈ 1.8e20 FLOPs ÷ (19e12 × 0.35) ≈ 8 小时
```

这个量级决定了：**4B 全量训练是「睡前挂机」任务，白天做数据与评测。**

# 02 · taskmon AI 分析对话（pi Agent 底座）

> 状态：**待批准**（2026-09-18 起草，审批门等待中）
> 创建：2026-09-18 · 项目：`taskmon/`（本仓库子项目）

## 背景与目标

taskmon 是 Windows 终端任务管理器（TypeScript + Bun 打包 exe）。目标：内嵌 **AI 分析对话**——
触发问答入口 → **第一条消息自动携带当前进程快照**（分组、内存、拓扑、命令行）→ 面板内循环追问。

底座评估结论（已调研确认）：**采用 pi coding agent v0.85.1 的 RPC 模式做模型接入底座，
taskmon 自己实现 Agent 层**（专属角色提示词、快照注入、chat 面板 UI）。理由：

- `pi --mode rpc` 是为嵌入第三方应用设计的 JSONL 协议（stdin 命令 / stdout 事件流），
  `prompt` / `abort` / `message_update(text_delta)` 即可覆盖"发送—流式收—中断"全链路；
- provider / API key / 流式协议 / 瞬态错误自动重试 / 上下文 compaction 全部复用 pi
  （本机已配 zhipu-glm、zai-coding-cn 供应商 + GLM-5.3，`~/.pi/agent/`）；
- `--no-tools --no-extensions --no-skills --no-context-files` 关干净后就是纯对话分析 Agent，
  无读写文件/执行命令风险；
- taskmon 侧仅用 `node:child_process` spawn + 行流解析，**零新增 npm 依赖**，
  与 CIM 采集（`src/cim.ts`）同款子进程模式，Bun `--compile` 兼容；
- 自研直连 OpenAI-compatible API 对比：需重做 key 管理、SSE 解析、重试、多轮上下文（约 +2~3 天），
  且脱离用户已有 pi/cc-switch 供应商体系，不采用。

## 决策回显（已与用户确认）

| 决策点 | 结论 |
|---|---|
| 底座 | pi RPC 模式（子进程），taskmon 自有 Agent 层；pi 缺失/失败时降级提示，主功能零影响 |
| 命令行隐私 | 快照**默认携带进程命令行**（区分同名进程），`--ai-no-cmdline` 可关；命令行截断 120 字符 |
| 会话生命周期 | **丢弃式**：`--no-session`，面板关闭/退出 taskmon 即结束会话；持久化恢复归二期 |
| `--ai "<问题>"` 一次性模式 | **二期**，一期聚焦 TUI 内嵌对话 |
| 模型选择 | 用 pi 默认（zai-coding-cn/glm-5.3）+ `--ai-model <pattern>` 可选覆盖转发 |
| 触发按键 | `i`（当前空闲）打开 AI 面板，Esc 中断/关闭 |

## 关键设计

### 模块一：`src/ai/piagent.ts` — pi RPC 子进程客户端

职责：spawn pi、JSONL 读写、事件归约为回调、abort/close。依赖：仅 `node:child_process` + `node:process`。

```ts
export interface PiAgentCallbacks {
  onDelta: (text: string) => void;      // assistant 文本增量（text_delta）
  onThinking?: () => void;              // thinking 增量到达（仅用于状态条"思考中"）
  onSettled: (err?: string) => void;    // 一轮结束（agent_settled）；err 非空 = 该轮失败
  onError: (err: string) => void;       // 致命错误：spawn ENOENT / 协议失败 / 进程异常退出
}

export class PiAgent {
  constructor(cb: PiAgentCallbacks, opts?: { model?: string });
  start(): void;          // spawn 子进程；失败走 onError（不抛异常）
  send(text: string): void;  // {"type":"prompt","message":text}
  abort(): void;             // {"type":"abort"}，然后等待 onSettled
  close(): void;             // kill 子进程（面板关闭/程序退出）
  get busy(): boolean;       // streaming 中
  get modelLabel(): string | undefined; // get_state 响应里的 provider/model 显示用
}
```

**JSONL 解析必须独立成纯函数**（可单测）：

```ts
/** 增量喂入 stdout chunk，返回完整事件行；内部维护残留 buffer（按 \n 切、容忍行尾 \r） */
export function parseRpcLines(state: { buf: string }, chunk: string): unknown[];
```

pi 文档明确警告：**Node `readline` 不合规**（会在 U+2028/U+2029 处误切，JSON 字符串内合法），
必须手工按 `\n` 切分。事件归约规则：

| RPC 事件 | 归约动作 |
|---|---|
| `message_update` + `text_delta` | `onDelta(delta)` |
| `message_update` + `thinking_delta` | `onThinking()` |
| `agent_settled` | `onSettled()`，busy=false |
| `auto_retry_start` | 状态提示"重试中"（经 onThinking 通道，不新增回调） |
| `type:"response"` + `success:false` | 对 prompt 失败：`onSettled(error)` |
| stdout 断 / exit 非关闭中 | `onError` |

**spawn 参数**（固定集，禁用一切工具与发现）：

```
pi --mode rpc --no-session --no-tools --no-extensions --no-skills
   --no-prompt-templates --no-context-files --offline [--model <pattern>]
```

`windowsHide: true`。`--offline` 只禁启动期网络动作（catalog 更新），不影响 LLM 调用。

### 模块二：`src/ai/snapshot.ts` — 快照注入提示词

```ts
export interface SnapshotOptions {
  groups: ProcessGroup[];
  totalProcs: number;
  sysMem?: SysMem;
  includeCmdline: boolean;
  timestamp: Date;
}
/** 角色指令 + 紧凑 JSON 快照；纯函数，单测断言结构 */
export function buildSnapshotPrompt(o: SnapshotOptions): string;
```

- **角色指令不塞命令行参数**（Windows 命令行长度/换行坑），与快照一起放**首条 user 消息**开头。
  要素：Windows 内存分析助手身份；输入为快照 JSON 的格式约定；输出约定——中文、要点式、
  终端纯文本（避免宽表格与代码围栏，每行 ≤ 80 列）、只分析不行动。
- 快照 JSON 结构（紧凑短 key 省 token，约 150B/进程，300 进程 ≈ 45KB ≈ 2 万 token，可接受）：

```jsonc
{
  "time": "2026-09-18 12:00:00",
  "physMem": { "usedGB": 20.1, "totalGB": 31.7, "usedPct": 63.4 },
  "totalProcs": 312,
  "groups": [
    {
      "name": "node.exe", "count": 8, "totalMB": 4200, "pctOfPhys": 13.2,
      "procs": [
        { "pid": 1234, "mb": 900, "orphan": true, "parent": "Zed.exe",
          "cmd": "node --max-old-space-size=4096 ..." }
      ]
    }
  ]
}
```

- `cmd` 仅 `includeCmdline` 时输出、截断 120 字符、压平空白；`orphan`/`parent` 有值才输出；
  组按总内存降序，尊重当前 `--top` 过滤后的可见组。

### 模块三：`src/ai/chatview.ts` — chat 面板渲染（纯函数）

```ts
export interface ChatMessage { role: 'user' | 'assistant'; text: string; }
export type ChatPhase = 'starting' | 'idle' | 'streaming' | 'error';

export interface ChatFrameOptions {
  width: number;
  messages: ChatMessage[];
  input: string;              // 当前输入行内容
  phase: ChatPhase;
  error?: string;
  modelLabel?: string;        // 如 zai-coding-cn/glm-5.3
}
export function renderChatFrame(o: ChatFrameOptions): Frame; // 复用 render.ts 的 Frame
```

- header：`taskmon · AI 分析 · <model> · <phase 描述>`，与主视图同款固定区结构；
- body：消息按序渲染——user 行 `你 ▸ …`（bold），assistant 行 `AI ▸` 前缀 + 按 `displayWidth`
  wrap 缩进；消息间空行分隔；**不做 markdown 渲染**，原样文本换行；
- 底部输入行由 main.ts 的 `statusLine()` 分支渲染（`❯ <input>█` + 快捷键提示），
  phase 徽标：starting=`正在启动 pi…`、streaming=`回复中…（Esc 中断）`、error=红色错误文本；
- 不含光标/滚动元数据（`groupRows` 为空），滚动用 main.ts 既有 `offset` 机制，新内容贴底跟随。

### main.ts 集成

- `viewMode` 扩展为 `'group' | 'tree' | 'chat'`；
- `chat` 状态：`{ agent?, messages: ChatMessage[], input: string, phase: ChatPhase, error?, offset } | undefined`；
- **`i` 键**：进入 chat 视图；首次惰性 `PiAgent.start()`（失败不进面板，showNotice 降级提示）；
  start 成功后自动 `send(角色指令 + 快照)`，phase `starting → streaming`；
- **chat 视图按键**（keyloop 最前分流）：可打印字符/Backspace 编辑输入行；Enter（idle）发送追问
  （user 消息回显 + `send`）；Esc：streaming 中 = `abort()`（等待 settled 回 idle），idle = 关闭面板
  （`agent.close()` + viewMode 回 group）；↑↓/PgUp/PgDn 滚动历史；`q`/Ctrl+C 仍走全局退出；
- **流式重绘节流**：text_delta 高频，draw() 100ms 节流（时间戳判断）， settled 时强制补一帧；
- **生命周期**：`quit()` 与面板关闭必须 `agent.close()` 杀 pi 子进程（`windowsHide`，
  杜绝自己制造孤儿进程）；spawn ENOENT → phase `error` 显示"未检测到 pi（npm i -g @earendil-works/pi-coding-agent），已降级"；
- **CLI 参数**：`--ai-model <pattern>`（透传 pi `--model`，字符白名单 `[A-Za-z0-9._:/-]` 校验），
  `--ai-no-cmdline`（快照去命令行）。

## 踩坑预防

1. **Windows spawn `pi`**：node spawn 不解析 PATHEXT（pi 实为 `pi.cmd`）→ `spawn("pi", args, { shell: true })`；
   shell 拼接有注入面 → 参数全部固定集 + `--ai-model` 白名单校验，杜绝自由文本入参。
2. **readline U+2028/2029 坑**：JSONL 手工按 `\n` 切（pi 官方文档明确警告），parseRpcLines 单测覆盖。
3. **角色指令注入方式**：不用 `--system-prompt`（命令行长度/换行歧义），放首条 user 消息。
4. **exe 场景**：`process.execPath` 是 taskmon.exe 自身，不可用 node 跑 cli.js 兜底；spawn pi 失败直接降级提示。
5. **孤儿防护**：pi 子进程 `windowsHide` + close/quit 必杀；树视图天天标别人 `†`，自己不能制造孤儿。
6. **流式重绘**：text_delta 高频直接 draw() 会吃 CPU → 100ms 节流，settled 强制补帧。
7. **编码**：rpc 事件流为 UTF-8 JSON，无 OEM 陷阱；但若走 `-p` 模式才需注意（一期不涉及）。
8. **首条消息体积**：命令行截断 120 字符/进程，防快照爆炸；如遇超长再议分组截断策略。

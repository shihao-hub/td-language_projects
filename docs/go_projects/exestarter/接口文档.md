# exestarter 接口文档

> 面向消费方（tooldeck GUI bridge、脚本、LLM 客户端）的联调契约。
> 与实现同源维护：改动 CLI 输出时必须同步更新本文档。
> 版本：2026-09-12（tag / update 子命令加入后）

## 1. 协议总则

### 1.1 JSON 包络

stdout 永远输出**单条合法 JSON**（紧凑单行；`--pretty` 时缩进），包络两种：

```json
// 成功
{"ok":true,"data":<任意 JSON 值>}
// 失败
{"ok":false,"error":{"code":"<机器可读错误码>","message":"<人读中文描述>"}}
```

- 业务代码禁止绕过 Emit/Fail 出口直接打印，stdout 不会出现包络外的内容
- `data` 的结构由各命令定义，见逐命令章节

### 1.2 stdout / stderr 分工

| 命令类别 | 错误输出去向 | 说明 |
|---|---|---|
| 管理命令（scan/list/add/remove/prune/tag/update/open/shell/version/help） | stdout（错误包络） | stdout 永远合法 JSON |
| 透传命令（run） | stderr（错误包络） | stdout 归属子进程，不能污染 |

### 1.3 退出码表

| 退出码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 管理命令失败（错误包络见 stdout）/ run 的 spawn 失败 |
| 子进程码 | run 透传时 = 子进程退出码 |
| 127 | run 未注册或条目失效（借 shell "not found" 惯例） |

### 1.4 全局 flag

- `--pretty`：缩进 JSON 供人读；可位于子命令前后
- 例外：`run` 的透传段（`run <name>` 之后的 args）不剥离 `--pretty`，原样传给子进程

### 1.5 并发约束（重要）

exestarter 无文件锁，**每次调用进程级读写 `UserConfigDir/exestarter/config.json`**。
消费方**不得并发调用写类命令**（add/remove/prune/tag/update/scan --add），
否则配置会互相覆盖。GUI bridge 应维护串行队列（tooldeck 已实现）。

## 2. 通用错误码表

| code | 语义 | 典型触发 |
|---|---|---|
| `bad_args` | 参数不合法 | flag 缺值、非法枚举、位置参数数量不对、非 .exe 路径 |
| `not_found` | 条目未注册 | remove/tag/update/run/open/shell 的 name 不存在 |
| `conflict` | 冲突 | 路径已注册、存在多个同名条目（提示手改配置文件区分） |
| `file_not_found` | 文件不存在 | add 的 exe 不存在、run/open 的条目已失效 |
| `internal` | 内部错误 | 配置保存失败、扫描失败、打开资源管理器失败 |
| `spawn_error` | 子进程启动失败 | run 的 exe 无法 spawn（走 stderr） |

## 3. 数据模型

### 3.1 Entry（条目）

`add` / `tag` / `update` 的 `data` 直接输出条目（空标签字段省略）；`list` 输出条目数组（含运行时 `valid`，空标签输出空串）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 调用名；默认 = 文件名去 `.exe`；update 改路径后跟随新文件名 |
| `path` | string | 绝对路径（Clean 后） |
| `added_at` | string | 添加日期；add 时写 `YYYY-MM-DD`（旧数据可能是 RFC3339） |
| `sys_tag` | string | 系统标签枚举，空 = 无；仅在非空时输出（Entry 序列化 omitempty） |
| `user_tag` | string | 用户标签自由文本，空 = 无；仅在非空时输出 |
| `valid` | boolean | **仅 list 输出**：运行时 os.Stat 结果，文件存在 = true |

### 3.2 SysTag 枚举（与 model/tags.go 对齐）

| key | 中文 | 颜色（RGB） |
|---|---|---|
| `todo` | 待完善 | `#E08A00` 橙 |
| `verify` | 待验证 | `#2070C0` 蓝 |
| `broken` | 有问题 | `#C03030` 红 |
| `stable` | 稳定 | `#309040` 绿 |

## 4. 命令详解

### 4.1 scan —— 扫描目录收集 exe

```
exestarter scan [--dir D] [--add]
```

| 参数 | 类型 | 必填 | 默认 | 约束 |
|---|---|---|---|---|
| `--dir` | string | 否（与上次记录二选一） | 上次扫描目录 | 必须是存在的目录 |
| `--add` | bool | 否 | false | true 时全部注册（按路径去重） |

递归扫描跳过噪音目录（node_modules、.git、.venv、__pycache__ 等），保留 dist/；单目录读取失败跳过不中断；上限 1000 条。

**仅预览成功响应**（tooldeck 扫描导入用这个）：

```json
{"ok":true,"data":{"dir":"D:\\Tools","count":2,"exes":["D:\\Tools\\a.exe","D:\\Tools\\sub\\b.exe"]}}
```

**--add 成功响应**：

```json
{"ok":true,"data":{"dir":"D:\\Tools","found":5,"added":3,"skipped":2}}
```

可能错误码：`bad_args`（无 --dir 且无记录 / 目录不存在）、`internal`（扫描/保存失败）。

### 4.2 list —— 条目清单

```
exestarter list [--status valid|invalid] [--tag T]
```

| 参数 | 类型 | 必填 | 默认 | 约束 |
|---|---|---|---|---|
| `--status` | string | 否 | 全部 | 仅 `valid` / `invalid` |
| `--tag` | string | 否 | 全部 | 精确匹配 sys_tag 或 user_tag |

**成功响应**（空结果输出 `[]` 而非 `null`）：

```json
{"ok":true,"data":[{"name":"alpha","path":"D:\\Tools\\alpha.exe","valid":true,"sys_tag":"todo","user_tag":"常用","added_at":"2026-09-12"}]}
```

可能错误码：`bad_args`（--status 非法值）。

### 4.3 add —— 注册单个 exe

```
exestarter add <path> [--name N] [--systag K] [--usertag T]
```

| 参数 | 类型 | 必填 | 默认 | 约束 |
|---|---|---|---|---|
| `<path>` 位置参数 | string | 是 | — | `.exe` 后缀（大小写不敏感）、文件必须存在 |
| `--name` | string | 否 | 文件名去 .exe | |
| `--systag` | string | 否 | 无 | 枚举：todo/verify/broken/stable |
| `--usertag` | string | 否 | 无 | 自由文本 |

**成功响应**（输出新建的完整条目）：

```json
{"ok":true,"data":{"name":"alpha","path":"D:\\Tools\\alpha.exe","added_at":"2026-09-12","sys_tag":"todo","user_tag":"hello"}}
```

可能错误码：`bad_args`、`conflict`（路径已注册）、`file_not_found`。

### 4.4 remove —— 删除注册

```
exestarter remove <name>
```

**成功响应**：

```json
{"ok":true,"data":{"removed":"alpha","path":"D:\\Tools\\alpha.exe"}}
```

可能错误码：`bad_args`、`not_found`、`conflict`（重名）。

### 4.5 prune —— 清理失效条目

```
exestarter prune
```

不接受任何参数。清理全部 `valid=false` 条目。

**成功响应**：

```json
{"ok":true,"data":{"removed":2,"remaining":8}}
```

可能错误码：`bad_args`（传了参数）、`internal`。

### 4.6 tag —— 设置标签

```
exestarter tag <name> [--systag K] [--usertag T]
```

| 参数 | 类型 | 必填 | 默认 | 约束 |
|---|---|---|---|---|
| `<name>` 位置参数 | string | 是 | — | |
| `--systag` | string | 否 | 不变 | 枚举：todo/verify/broken/stable；**传空串 = 清除**；未传 = 保持原值 |
| `--usertag` | string | 否 | 不变 | 自由文本；**传空串 = 清除**；未传 = 保持原值 |

**传空清除语义**：flag 是否"显式传入"由标准库 flag 的 Visit 语义区分——
`--systag= ` / `--systag ""` 是显式传空（清除），完全不写该 flag 才是"未传"（保持）。
注意 PowerShell 5.1 调用空串参数要用 `--systag=` 形式（`--systag ""` 的空参会被 shell 吞掉）。

**成功响应**（输出更新后的完整条目；下例 usertag 已被清除故省略）：

```json
{"ok":true,"data":{"name":"alpha","path":"D:\\Tools\\alpha.exe","added_at":"2026-09-12","sys_tag":"stable"}}
```

可能错误码：`bad_args`（非法枚举）、`not_found`、`conflict`（重名）。

### 4.7 update —— 改路径

```
exestarter update <name> --path P
```

| 参数 | 类型 | 必填 | 默认 | 约束 |
|---|---|---|---|---|
| `<name>` 位置参数 | string | 是 | — | |
| `--path` | string | 是 | — | `.exe` 后缀、文件必须存在、不得与其他条目重复（大小写不敏感 Clean 后比较） |

exe 搬家后只更新路径：**name 跟随新文件名**，标签与 added_at 原样保留。与旧路径相同视为无操作成功。

**成功响应**（name 已从 alpha 变为 gamma）：

```json
{"ok":true,"data":{"name":"gamma","path":"D:\\Tools\\moved\\gamma.exe","added_at":"2026-09-12","sys_tag":"stable"}}
```

可能错误码：`bad_args`、`not_found`、`conflict`（重名条目 / 路径已注册）、`file_not_found`。

### 4.8 run —— 前台透传启动

```
exestarter run <name> [args...]
```

- stdout/stderr/stdin 全部继承子进程，退出码 = 子进程码
- **透传豁免**：错误 JSON 走 **stderr**；未注册/失效 = 退出码 127
- GUI 消费建议：detached spawn、不等退出码；启动前用 list 的 `valid` 预检

**失败响应**（stderr）：

```json
{"ok":false,"error":{"code":"file_not_found","message":"文件已失效: D:\\gone\\alpha.exe"}}
```

可能错误码：`bad_args`、`not_found`、`file_not_found`、`spawn_error`。

### 4.9 open —— 资源管理器定位

```
exestarter open <name>
```

**成功响应**：

```json
{"ok":true,"data":{"opened":"D:\\Tools","selected":"D:\\Tools\\alpha.exe"}}
```

可能错误码：`bad_args`、`not_found`、`file_not_found`、`internal`。

### 4.10 shell —— exe 目录开 PowerShell

```
exestarter shell <name>
```

新窗口独立存活，CLI 立即返回 JSON。

**成功响应**：

```json
{"ok":true,"data":{"shell":"powershell","dir":"D:\\Tools"}}
```

可能错误码：`bad_args`、`not_found`、`file_not_found`（目录不存在）、`internal`。

### 4.11 version / help

```
exestarter version    # {"ok":true,"data":{"version":"dev"}}
exestarter help       # 命令表 + notes（含配置路径说明）
```

## 5. 消费方示例

### 5.1 PowerShell

```powershell
$out = exestarter list | ConvertFrom-Json
if ($out.ok) { $out.data | Format-Table name, valid, sys_tag } else { Write-Error "$($out.error.code): $($out.error.message)" }
```

注意：PowerShell 5.1 传空串参数会被吞，清除标签用 `--systag=` 形式。

### 5.2 Node（tooldeck bridge 真实参考实现）

```ts
import { spawn } from 'node:child_process'

const child = spawn(exePath, ['tag', name, '--systag', 'stable'], { windowsHide: true })
let out = ''
child.stdout.on('data', (c) => { out += c })
child.on('close', (code) => {
  const env = JSON.parse(out) // stdout 永远合法 JSON，直接 parse
  if (env.ok) console.log('更新成功', env.data)
  else console.error(env.error.code, env.error.message)
})
```

写类命令务必串行执行（见 1.5 并发约束）。

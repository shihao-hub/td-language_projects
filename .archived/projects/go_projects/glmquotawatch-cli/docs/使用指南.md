# glmquotawatch 使用指南

> 定时采样智谱 GLM（bigmodel）编码套餐用量，跨越阈值时弹 Windows Toast 通知的常驻 CLI 工具；MCP/CLI 双壳架构，AI 客户端可经 MCP 直接查询与配置。
>
> 项目位置：`go_projects/glmquotawatch/`（go_projects 子仓）。
>
> 更新：2026-09-15，第一版（对应 v0.1.0）。

## 1. 背景与设计

团队多人共用一个 GLM Coding Plan 账号：每人持独立 API token，消耗同一个账号的 5 小时滚动窗口额度。本工具在每个成员机器上常驻运行，用各自的 token 定时查询账号级用量，跨越阈值时本地弹 Windows Toast，实现「谁在跑谁收到提醒」。

- 用量接口：`GET https://open.bigmodel.cn/api/monitor/usage/quota/limit`，`Authorization: Bearer <token>`；返回 `limits[]`，其中 `TOKENS_LIMIT` 条目即 token 窗口（实测 max 套餐只有一条 5h 窗口，无周额度；代码按数组处理，未来加周额度自动兼容）。
- 架构遵循《[MCP 契约为先](<../MCP 契约为先.md>)》与《[CLI 与 MCP 双壳架构工作指南](<../CLI 与 MCP 双壳架构工作指南.md>)》：`internal/service` 是唯一业务真相源，`internal/cli`（cobra）与 `internal/mcp`（go-sdk v1.8.0）均为薄适配层；业务错误统一 `*service.Error{Code, Message}`，CLI 退出码与 MCP `IsError` 同源同文案。
- 告警状态机（`internal/quota`，纯逻辑）：跨档只报最高新档、记账全量；用量回落到 `min(thresholds) - hysteresis` 以下才重新武装（滞回防抖）；阈值配置变更即整体重新武装；状态持久化，进程重启不重复轰炸。

## 2. 构建与安装

依赖 Go 1.25+（GOPROXY 已配 goproxy.cn）：

```powershell
cd go_projects\glmquotawatch
go build -ldflags "-X glmquotawatch/internal/cli.Version=v0.1.0" -o glmquotawatch.exe .
```

把 `glmquotawatch.exe` 所在目录加入 PATH，或直接用相对/绝对路径调用。

## 3. 快速上手

```powershell
glmquotawatch token set <你的GLM_API_TOKEN>   # bigmodel 开放平台密钥，长度 ≥ 20
glmquotawatch status                          # 立即采样一次
glmquotawatch start                           # 启动常驻监控，Ctrl+C 停止
```

`status` 输出示例（与 CC Switch 配置用量查询面板语义一致）：

```
GLM 用量（套餐 max，采样于 2026-09-15T18:45:22+08:00）
  5h 窗口          4%    已通知档位: 无，距下次刷新还有 3h34m
```

## 4. 命令参考

| 命令 | 说明 |
|---|---|
| `token set <token>` | 配置 token（trim 后长度 ≥ 20） |
| `token show` | 查看配置（token 脱敏：前 8 后 4） |
| `token remove` | 清除 token（幂等） |
| `status [--json]` | 立即采样：请求上游 → 落采样历史 → 推进告警状态（**不发通知**）；`--json` 输出信封 |
| `config show` | 查看全部配置与数据目录 |
| `config set <key> <value>` | 修改配置，见下表 |
| `start` | 常驻监控：单实例锁 → 立即采样一轮 → 按间隔轮询；跨阈值弹 Toast；`interval` 手改文件热加载；Ctrl+C 优雅退出 |
| `mcp` | 以 stdio MCP server 运行 |
| `schema` | 导出与 `tools/list` 同源的 MCP 工具定义（离线检查） |

全局选项：`--json` 以 `{"ok":true,"data":...}` / `{"ok":false,"error":{"code","message"}}` 信封输出；退出码 0 成功、1 业务失败、2 参数错误。

### config set 键与校验

| 键 | 规则 | 默认 |
|---|---|---|
| `interval` | 正时长，clamp 到 [30s, 24h]（如 `90s`、`5m`、`1h`） | `5m` |
| `thresholds` | 逗号分隔，每项 1..99，自动排序去重 | `50,60,80,90` |
| `hysteresis` | 0..30（百分点） | `5` |
| `silent` | `true` / `false`（通知静音） | `false` |

### 错误码

`no_token`（未配 token）、`bad_args`（参数不合法）、`bad_value`（配置值非法）、`unknown_key`（未知配置键）、`locked`（已有实例运行）、`api_error`（上游非 2xx）、`upstream_error`（上游业务码非 200）、`internal`。CLI 与 MCP 同码同文案。

## 6. 数据文件与目录

全部位于 `%APPDATA%\language_projects\glmquotawatch\`（取不到 `AppData` 回退 `~/.language_projects/glmquotawatch/`）：

| 文件 | 内容 |
|---|---|
| `config.json` | 配置；**token 本机明文保存**（与仓内 quickask 同做法） |
| `state.json` | 告警武装状态（已通知档位 + 阈值指纹）；损坏时按空状态继续，代价是可能补发一条通知 |
| `samples-YYYY-MM.jsonl` | 采样历史，按月分文件；行结构 `{"ts":"<RFC3339>","data":<上游 data 原文>}`，失败采样不落盘；二期突发消耗检测的数据源 |
| `daemon.lock` | 单实例锁（PID 存活检测）；残留死锁文件可直接删除 |

环境变量 `GLM_QUOTA_WATCH_API_BASE` 可覆盖上游地址（默认 `https://open.bigmodel.cn`；测试注入用，将来可指 z.ai 国际版）。

## 7. 通知不弹排查

程序侧成功后会记日志 `msg=通知已发送`；有这行而屏幕无弹窗即为系统侧丢弃：

1. Windows 设置 → 系统 → 通知：总开关开启，且「Windows PowerShell」应用的通知权限开启（通知以 PowerShell 注册 AUMID 身份发出，归在 PowerShell 名下）；
2. 勿扰 / 专注助手是否开启；
3. 日志连 `通知已发送` 都没有：检查 `powershell` 是否在 PATH（go-toast 经 PowerShell 调 WinRT 投影；PS 7（pwsh）不支持该投影，工具固定调用 `PowerShell` 5.1 不受影响）。
